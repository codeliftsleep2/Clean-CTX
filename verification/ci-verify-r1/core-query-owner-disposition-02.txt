# CI-VERIFY-R1 — Owner Disposition 02
## Closed Registration of Complete Core IR Queries

Agent MaxHeadRoom,

The proposed bounded extension of the existing closed query registration mechanism is approved under the AGENTS.md Architectural Approval Gate.

The confirmed RED demonstrates redundant compilation of an invariant complete IR query during warmed execution. The reported capture and IR equality assertions passed.

This authorization permits reuse of the complete binary-owned TypeScript and C# IR query definitions. It does not authorize general-purpose query caching.

## 1. Authorized implementation

Approve the proposed extension involving:

- src/ir/pipeline/core.rs
- src/ir/pipeline/core/query_definition.rs
- src/compression/capture_pipeline.rs

Approve the additional closed registration identities:

- RegisteredQuery::TypeScriptIR
- RegisteredQuery::CSharpIR

Reuse the existing registered-query OnceLock mechanism.

Preserve a single authoritative composition mechanism for the complete IR query definitions.

The registered and dynamic paths must consume equivalent query definitions rather than maintain independently evolving copies.

Registration eligibility requires the exact supported binary-owned base definition and its matching grammar.

Arbitrary, custom, runtime-dependent, mismatched-grammar and otherwise unregistered queries must retain their existing dynamic compilation behavior.

No additional language registrations are authorized by this disposition.

## 2. Architectural dependency review

Before applying the proposed implementation, verify the architectural validity of the dependency from compression/capture_pipeline.rs to CoreIRPass::complete_query_definition.

The IR producer already consumes the capture pipeline.

Do not introduce an architectural layer violation merely because Rust permits the resulting module references.

If the proposed dependency conflicts with an existing controlling architectural requirement, identify the smallest compliant ownership arrangement.

Reuse existing mechanisms.

Do not introduce a generic query registry, plugin system, dependency injection framework or new caching architecture.

If a compliant arrangement requires a material architectural expansion, stop and return the decision.

## 3. Prior decision amendment

The earlier disposition in SEMANTIC_QUERY_PERFORMANCE_ARCHITECTURE_IMPLEMENTATION_2026-10-16.md explicitly retains dynamic compilation.

Approve a narrow prospective amendment:

Retain dynamic compilation for arbitrary, custom, runtime-dependent and unregistered query definitions. Permit closed registration of the complete binary-owned TypeScript and C# IR query definitions when their exact definition and matching grammar are established.

Preserve the earlier decision and its historical applicability.

Do not reinterpret this amendment as authorization for arbitrary query-text caching.

Prepare the applicable protected-authority amendment and obtain the required B11 owner-operated authorization.

This disposition is not itself a generated predecessor-bound authorization artifact.

## 4. Required semantic preservation

Preserve:

- Exact complete query composition and ordering.
- Capture names, identities, ordering and multiplicity.
- TypeScript declaration and invocation semantics.
- C# invocation and semantic captures.
- All existing NgRx query contributions.
- Fidelity-dependent processing.
- Source parsing and parser behavior.
- Independent query cursor state.
- Existing error and refusal behavior.
- Dynamic/custom query semantics.
- Existing feature and grammar applicability.
- Resulting canonical IR behavior.

Do not cache source trees, captures, cursors, source-dependent semantic results or workspace authority.

The compiled query must remain immutable and independent of source, workspace, runtime configuration and fidelity.

Verify that every query composition input satisfies that condition.

## 5. Cache correctness and lifecycle

Preserve the existing closed registration lifecycle.

The extension adds exactly two bounded process-lifetime registrations.

Verify:

- Cold initialization.
- Warm reuse.
- Concurrent first access.
- Independent concurrent query execution.
- Grammar identity correctness.
- Feature-disabled behavior.
- Compilation failure handling.
- Dynamic fallback behavior for nonregistered definitions.

The existing cached compilation-error semantics may be reused only where the complete definition and grammar are genuinely immutable.

Do not introduce retries, eviction, global query maps, synchronization around source parsing or new cache invalidation mechanisms.

## 6. RED/GREEN verification

Establish focused coverage for both TypeScript and C#.

Demonstrate exact equivalence between the registered and dynamic complete-query paths across applicable existing fixtures.
