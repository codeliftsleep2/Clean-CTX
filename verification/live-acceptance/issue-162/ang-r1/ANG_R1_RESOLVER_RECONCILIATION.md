## Exact evidence and producer ownership

`TypeScriptAuthority` owns `resolve_mappings: Vec<ResolveMapping>` with serde default
alongside declaration facets, demanded occurrences, runtime reference sites, separate
type reference sites, package proof and witnesses. `ResolveMapping` records source,
source hash, owning route Object, outer field pair/key, nested mapping Object,
mapping pair/key, decoded name and value spans. It is private language evidence;
no framework role or public key contract is encoded by its existence.

`declaration_facets/objects.rs::Demand::object` recognizes the demanded ordinary
`resolve` Object and calls `resolve_mappings.rs::Demand::resolve_object`.
Ordinary identifier/member-reference values acquire the mapping join through the
existing resolver. Other ordinary named values retain key/pair spelling and an
Unsupported value without recursively evaluating contents. Computed/spread/shorthand
structure retains an unknown-key Unsupported marker.

`TypeScriptAuthority::resolve_mapping_at` replays exact source/hash and containment,
decoded outer `resolve` and inner key tokens, demanded pair structures, unique
owner/Object/field association, demanded resolved reference and the retained value
facet. It checks witness currentness, rejects crossed/borrowed/competing records
and requires the external target's consumed content witness. It performs no parsing,
name recovery, new resolution or text fallback at replay.

`route_objects::project` establishes source-owned const native `@angular/router`
Routes annotation/initializer proof, exact Object and children/path structure.
`RouteObject::subject` builds the existing RouteOccurrence using the root declaration
and actual source/hash/Object span. Equal path labels do not equate occurrences.

`route_resolvers::project` then requires the unique ordinary `resolve` Object,
source-current demanded structure and one mapping record for that exact owner,
Object, decoded name and value. Exact `resolve_mapping_at` and `value_reference_at`
must agree. A BTreeSet deduplicates selected DeclarationIds **per route object**;
the emitted relation is `ResolvedBy(RouteOccurrence, DeclarationId as Resolver)`.

The canonical endpoint lives in the semantic edge/snapshot/index path, separate
from the language-agnostic CoreOp instruction stream. Existing public endpoint JSON
hides the private canonical coordinate. No new CoreOp or codec is required merely
to retain this existing written membership.

## Refusal and preservation behavior

| Case | Actual implementation behavior / limit |
| --- | --- |
| Runtime function, class, typed functional value or noncallable value | Can be a written reference when exact declaration proof succeeds; this is not callable eligibility. |
| Type-only imported target | Does not gain runtime value authority from its type reference. A type-only Routes annotation may separately prove the root. |
| Direct, alias, barrel, namespace and local target | Same declaration mechanism; historical tests explicitly cover five forms. |
| Distinct ordinary keys selecting one target | Retained mappings remain distinct; one public object/target support. |
| Duplicate decoded key, including escaped spelling | Refuse that key; independently unique ordinary named siblings survive. |
| Unsupported ordinary named value | Refuse its value locally while retaining its key so it cannot conceal a duplicate. |
| Unresolved or ambiguous named target | No canonical relation for that mapping; a valid target elsewhere cannot repair it. |
| Competing outer resolve fields | Refuse the resolver container; do not choose first/last. |
| Unknown computed/spread/shorthand key structure | Cannot certify unique named mappings for that container. |
| Call, inline callback, nested value or arbitrary expression | No new evaluator or recursive mapping support. |
| Multiple independently valid route objects with equal paths | Distinct RouteOccurrence supports survive. |
| Duplicate/crossed field, mapping, key or target proof | Refuse; no generic endpoint-only exception. |
| Native owned resolve field, canonical refusal | Suppress its weak legacy contribution regardless of canonical success. |
| Outside admitted native ownership | Existing generic noncanonical compatibility behavior survives; it is not canonical support. |
| Other guard/component/loadChildren/provider fields | Remain independent; resolver refusal does not justify sweeping sibling facts. |

The actual routing stage computes `route_resolvers::owned_objects` before
`RouteShape::to_semantic_edges_resolver_ownership`, then appends the canonical
projection. Suppression selects actual object provenance before flattening,
not matching names or paths. Retained admission in `relation_evidence.rs` lazily
constructs that exact resolver projection once per synchronous admission call
and compares layer/relation/domain/type/name/file/canonical coordinates.
Legacy `(None,None)` facts remain legacy; canonical refusal cannot downgrade.
