## Located producer/admission boundary

provider_semantics::project_at selects composed entry traversal only when
provider_composition::component_owner proves a Component. Directive/Module
ordinary positions remain immediate-array syntax paths. A reference root cannot
satisfy that path; nested/spread children are not terminal provider entries.

The same Component-only predicate controls retained entry selection in
registration_token and pair_at. Imported projection/admission explicitly selects
only Components and constructs a Component registration subject. Merely widening
producer traversal would therefore leave retained replay and owner rendering wrong.

There is a further admission boundary: admits_registration expects a Component
subject, and neutral relation_evidence routes canonical ordinary Component facts
through it. A newly admitted composed Directive/Module registration must not fall
back to generic endpoint admission if its membership proof is missing. A valid
owner/token elsewhere does not establish this provider entry or position.

Position::admits already distinguishes ordinary Component/Directive/Module from
Component-only View. Existing source-qualified traversal, demanded occurrences,
canonical tokens, strategy-entry policies and the source-owned durable lifecycle
can be reused. No new proof payload or carrier is demonstrated as necessary.
