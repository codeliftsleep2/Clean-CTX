## Causal and carrier trace

The earliest located explicit refusal is provider_composition::visit's
same-source/source-hash guard. Actual retained imported GROUP structure is present
in all six cases. This differs from the earlier viewProviders acquisition loss.

Removing that guard is insufficient and unsafe. provider_semantics::project_at
parses app.ts and selects entries from its syntax tree using terminal byte spans.
Foreign offsets can overlap unrelated owner syntax. registration_token, pair_at
and canonical_token replay terminal membership and call value_reference_at.

TypeScriptAuthority.reference_sites is captured from the owning file and stores
only (start, end, resolution). Its accessor has no occurrence-source argument.
ExpressionFacet likewise stores unqualified spans; containing DeclarationFacet
retains a source-qualified DeclarationId. Demand::reference resolves nested
references against their actual file during capture, but does not add those
foreign sites to the owner's reference_sites inventory. Treating a foreign facet
as an owner-file site would confuse occurrence authority with target identity.

Existing demanded declaration structure and Host witnesses are useful carriers.
Module composition's declaration-set leaves do not establish provider entries.
The public owner/token relations already express this question, but exact
cross-source occurrence association must survive capture, retained replay,
durable restoration and publication before those relations may be emitted.
