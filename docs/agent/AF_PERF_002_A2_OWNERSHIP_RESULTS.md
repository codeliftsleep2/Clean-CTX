### A2a versus A2b: current construction-inclusive judgment

Original: six consumer-local class traversals per demanding owner, pure role checks,
then family-specific owner and payload joins. Owner-negative/role-negative paths
short-circuit differently. Our counters measure first-stage visits, not separate
complete timings or every nested role-attribute comparison.

A2a as proposed: F class sweeps, two ownership checks per class and borrowed lists,
then existing selectors over those lists. For the two-owner/all-partial density
fixture every class belongs to both owners: both views retain C references per
owner, so all six original class traversals still occur over equally sized lists.
Construction adds work without reducing consumer visits in that case. In sparse
ordinary-owner fixtures it may reduce role visits, but requires owner checks for
negative-role classes that currently skip most such checks. Retaining FC is explicit.

A2b: one coordinator class sweep plus class-file/method-owner entries and ordered
bucket allocations. It can remove repeated outer owner selection when classes are
sparse across owners. It still retains all classes per owner for all-owner partials,
and leaves raw-part/method joins unchanged unless separately redesigned. At two
owners/sixteen all-owner classes, bucket reference payload alone is64 borrowed
class references across the two maps (before headers/capacity/allocation). This is
an analytical element count, not a measured allocation or approved implementation.

**Recommendation:** do not implement A2a verbatim based on this packet. Its benefit
is workload-dependent and its added construction is not yet justified against
all-role-negative and all-owner-partial cases. Keep A2 as DESIGN REVIEW/MONITOR;
return a revised, explicitly scoped proposal only if it avoids adding full-owner
selection to unreachable consumers and shows a construction-inclusive opportunity.
A2b remains separately controlled; no automatic escalation to cross-owner buckets.
The next consequential independent investigations may proceed without waiting for
A2 optimization. No speculative cache, generic context or shared publication state.
