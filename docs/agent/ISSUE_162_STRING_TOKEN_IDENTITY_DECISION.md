## Requirement and located gap

AQ08/AQ09 require the actual DI token and consumers; AQ25 requires exact joins
and current provenance. Existing consumers are constructor_authority,
inject_authority and provider_semantics, exposed through registered
workspace_query. The [Angular Inject API](https://angular.dev/api/core/Inject)
accepts a custom token, including a string, rather than making an unrelated
parameter type its runtime identity. The approved constructor contract explicitly
left primitive-token interpretation undecided; this record makes that decision
concrete before changing production behavior.

At proposal time, implementation supported canonical reference-valued tokens. Literal
constructor arguments remain ExpressionValue::Unsupported and use the explicitly
unmigrated legacy annotation projection. Providers already have a string syntax
branch in provider_semantics::token_identity, which reads a fragment; it is not
canonical string-value proof or a complete escape decoder.

CanonicalEndpoint contains a CanonicalDeclaration and optional asserting site.
EdgeKey, DurableEntityRef and relation admission carry that evidence. A string
value has no declaration. Fabricating a DeclarationId for the literal or using
the annotation class would misstate authority; using only a rendered token name
would lose typed identity and confuse strings with object/class tokens.
That finding preceded the observed literal-token RED recorded above. No oracle
run is claimed. Existing reference-token tests and receipts remain preserved.
