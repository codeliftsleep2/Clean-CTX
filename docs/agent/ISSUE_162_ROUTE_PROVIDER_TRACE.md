## Architectural decision to resolve after behavioral evidence

Class-owner composition approval does not authorize route-root acquisition or
new route occurrence identity. Before production repair, define the exact native
Routes/configuration proof and a route-object identity that survives retained
replay, publication keys, restoration and public queries. Display path remains
presentation and cannot be the sole provider-owner discriminator.

Alternatives are an exact route-object occurrence anchored to its proved
configuration root, a broader explicit configuration/route context carrier, or
deferral. Prefer the smallest occurrence-qualified route owner through existing
authority and transport, subject to a concrete carrier/consumer audit. Do not
choose an encoding or expand global EntityRef equality in this investigation.
An undifferentiated file/config owner would lose which route contains the entry.

The intended two-test omission evidence does not decide that identity contract.
After a valid RED, preserve unchanged test/registration/log bytes, trace the
bounded carrier and request explicit approval before implementing new authority.
