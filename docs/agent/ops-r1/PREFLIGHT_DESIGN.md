# OPS-R1 mandatory agent architectural preflight design

Agent MaxHeadRoom. Candidate integration, not a second approval engine.

## Reuse the existing source-owned workflow

AGENTS.md already requires architectural approval and pcg-authoring.md retrieval.
B11 owns source declarations, accepted predecessor and protected authorization.
The proposed extension makes implementation evidence include the following compact
boundary record; it does not create a new registry service or authorization token.

| Required pre-implementation field | Existing source / enforceable observation |
| --- | --- |
| Affected boundary and production entry path | Changed producer/consumer source paths, operation scope and source hashes |
| Controlling architecture/revision | Actual returned PCG unit/component references and acquired source content; accepted authority SHA |
| Historical failure patterns | Applicable AFP entries with historical witness/evidence, not just keyword match |
| AFF/GARC obligations | Exact approved invariant and package/target/feature test identities; unresolved cases explicit |
| Shared consumers | Current call-path census, specialized versus shared authority and lifecycle |
| Negative counterexamples | Exact unchanged regression or proposed witness; RED standing separated by evidence class |
| Feature configurations | Supported relevant modes and required compile/list/runtime obligations |
| Approval | Existing task/owner disposition; exact cross-cutting decision still held if not authorized |
| Completion evidence | Expected GREEN, source/currentness/lifecycle, actual admission and applicable field boundary |

## What can be enforced

Reuse source-owned components on the implementation mission and existing checker
to require declared fields for designated protected-boundary changes, after owner
approval of the scope/predicate. Reuse existing structural source analysis for
well-defined module edges; unresolved macro/dispatch/call-graph applicability must
produce a visible review obligation, not a false proof. Compare actual changed
context/revisions; do not restart unrelated investigations for unrelated graph drift.

Require an accepted preflight source revision before cross-cutting implementation
in the agent workflow. At publication recheck drift and preserve the record linking
source, authority and tests. A retrospective checklist cannot prove it happened
before implementation. Enforcing chronological ordering needs integration with
the existing workflow boundary, not a claim inferred from final Markdown.

## What cannot be mechanically certified

Graph traversal establishes structure; content acquisition is not comprehension,
conflict resolution or authorization. A filled field does not prove honest shared-
consumer analysis. An AST path scan cannot resolve arbitrary runtime/macro dispatch.
The checker must not manufacture owner approval from existing production behavior.
Absent host PCG tools must be disclosed and acquired through the operator-owned
existing production driver; never silently replace authority with memory.

## Proposed protected change and cost

Prepare a narrow update to the existing agent/architecture procedures and, if
needed, document admission field applicability. Do not edit AGENTS.md as a competing
ruleset. Owner approves the live engineering authority and tracked projection
together, with B11 descriptor/membership/protection review where applicable.
Run one relevant context closure and selected source acquisitions per meaningful
boundary, reuse still-current task context, and recheck relevant drift. No whole-
repository knowledge dump or per-line repeated preflight is proposed.
