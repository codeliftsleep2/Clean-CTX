## Why this decision is necessary

The approved config slice proves declaration membership, explicitly excluding
bootstrap selection. AQ14 needs root/config linkage, but the current relation
vocabulary has no such fact and the canonical endpoints have no general call-site
occurrence. Transient invocation evidence is discarded at artifact return.
Adding only producer edges would leave retained admission/restoration unable to
replay the asserted association. Reusing RegistersProvider, a route occurrence,
or the imported API declaration as subject would change their meanings.
See the [causal/carrier trace](ISSUE_162_BOOTSTRAP_REFERENCE_TRACE.md).

## Recommended bounded contract

- Admit calls to the exact native public @angular/platform-browser
  bootstrapApplication value, through resolver-proved direct, aliased, barrel
  and namespace routes. Reject foreign/shadow/type-only/unresolved/ambiguous
  callees. Written names alone grant no role.
- Initially support ordinary non-spread root/config reference arguments. Root
  identity must join the actual argument occurrence to an existing native
  Component declaration. Config identity must join its actual argument to an
  exact native const ApplicationConfig object declaration, local or imported,
  using proved alias routes and actual source-qualified type/package evidence.
  A missing optional config argument emits no config relation.
- The proposed slice records the declared call site even if enclosed in a
  function or conditional. Retain exact native call/container/argument structure;
  do not infer reachability, standalone validity or successful Angular execution.
  Existing declaration-role limits remain unchanged.
- Preserve independent proved root association when a config route is unsupported;
  classify answers as structural lower bounds. Do not infer missing argument
  meaning, a default config, or complete application membership.
- Give each call a private source/hash/span occurrence endpoint with exact retained
  source-owned structural proof. Prefer a bounded neutral invocation occurrence
  carrier in the existing TypeScriptAuthority payload over persisting the whole
  transient evidence set. Do not fabricate a DeclarationId for a call or change
  canonical declaration/string/route identity or EntityRef equality.
- Producer and retained relation admission must replay the same exact native API,
  call, argument and target joins. Missing/crossed/shifted/forged/competing proof
  cannot downgrade into generic endpoint acceptance.
- Reuse existing resolver/Host acquisition, witnesses, source-owned artifacts,
  session/SQLite transport, index/publication, replacement and retirement. No
  new resolver/cache/registry/budget or independent lifecycle. Advance semantic
  compatibility and durable compatibility where changed proof meaning requires.
- Keep existing public query fields/selectors. Expose the two proposed relation
  values and subject type through current forward/reverse answers, preserving
  multiple call occurrences even when their labels/root/config targets coincide.
  Test exact public owner/target file multisets; if the current surface cannot
  distinguish required answers, stop for that specific contract decision.

This authorizes no inline config object ownership, mergeApplicationConfig,
EnvironmentProviders evaluation, bootstrapModule/platform receiver chain, provider
precedence/multi, runtime app instance, effective injector visibility, consumer
satisfaction or AQ14/P3/P1/W04/#162 closure. These remain required broader work,
not facts silently excluded from a claim of completeness.
