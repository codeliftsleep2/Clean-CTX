## Recommended bounded contract

1. Generalize the existing internal canonical relation endpoint carrier to
   distinguish declaration endpoints from proved string-token values. Keep its
   existing source ownership, generation, compatibility, durable transport,
   index deduplication, selection and retirement. Do not introduce a parallel
   literal-token overlay, registry, cache or publication lifecycle.
2. TypeScript retains the demanded literal occurrence, source/hash/span and exact
   language string value independently of Angular roles. Preserve JavaScript
   string code units and escape meaning; do not case-fold or Unicode-normalize.
   Equivalent quote/escape spellings denote the same value; different values
   remain distinct. Preserve invalid/unsupported/unavailable outcomes, not guessed
   values. No arbitrary expression evaluation or complete type checker is implied.
3. Angular admits that value as a DI token only after actual Inject/inject or
   provider-role/owner proof. Token equality does not prove a provider satisfies
   a consumer: the required application/injector scope and precedence remain
   separate obligations. Equal InjectionToken descriptions must not create equal
   token identities; string and declaration/object-token variants stay distinct.
4. Retain occurrence/provenance proof separately from value equality. Equal string
   values may join across source sites only in the proved applicable semantic
   context; each asserting source keeps its own facts and witnesses. Source edits,
   dependency/config/package changes, deletion and restore must invalidate or
   replace the appropriate proof. Cache/query history is not context authority.
5. Reuse demanded immutable initializer/alias evidence where an admitted const or
   barrel route supplies a string token. Mutable, cyclic, competing or unproved
   value derivations cannot become constant-string proof. Bound remaining forms
   with the existing question/fact/consumer ledger; do not silently exclude an
   established constructor, field or registration form.
6. Keep global EntityRef equality and public JSON schema unchanged. Deliberately
   render a canonical string token as a quoted, escaped literal label in existing
   name fields, e.g. the label `"audit.api"`, while a declaration token named
   AuditApi remains AuditApi. This makes the distinction visible without inventing
   a declaration file. File metadata remains existing provenance. Corresponding
   canonical provider token labels use the same rendering. This is an intentional
   name-value correction requiring this owner decision, not a schema change or
   blanket global string-label policy.
7. Preserve nonmigrated producers and permitted old-record legacy projections.
   Records lacking required string proof cannot serve migrated canonical facts;
   reacquire through the normal producer path and advance existing compatibility.
   Do not promote old name strings into typed token identity.

The exact Rust carrier and backward-compatible serialized shape should be chosen
only after tracing all current canonical endpoint uses. This approval would not
pre-authorize a global identity redesign, new selectors/status fields, generic
constant evaluator, numeric/boolean token policy, or Attribute semantics.
Those remaining obligations remain tracked, not silently certified or removed.

supported language value proof, quoted labels and existing lifecycle reuse.

TypeScript establishes value/occurrence evidence; Angular establishes each
consumer position's admitted token forms. Numeric/boolean/object literal policy,
Attribute, arbitrary evaluation and public schema changes remain undecided.

oracle or full version-family conformance. Selected fixture declarations model
