## [Unreleased]

### Added

* **Generic `Calls` IR fact — the instruction and its full serialization contract** — Clean-CTX had no way to express an invocation at all: `CoreOp` carried definitions, signatures, relationships, imports, control flow, and verbatim bodies, but no call/invoke variant, which is precisely why `GraphEdge::Calls` and `SemanticRelation::Calls` both existed as unreachable scaffolding with no producer. `CoreOp::Call(caller_method_id, callee_name, explicit_arg_count)` now carries exactly one structural invocation fact: the innermost callable containing the call in the same file, the callee name **as written at the call site**, and the number of explicitly written arguments (structural, from the argument-list node — never from `split(',')`, regex, or line scanning). The callee is deliberately a NAME and not a resolved declaration identity, because a call site carries no type information: two calls differing only in argument count stay distinguishable, two calls differing only in argument type remain honestly indistinguishable, extension-method receivers are never added to the count, and optional/`params` compatibility is never evaluated (that belongs to later resolution logic, if any). `CoreOp::call_parts()` mirrors the existing `body_span()` accessor so consumers that reason about invocations do not re-match the variant. Every hand-written encoding was extended rather than regenerated: **named wire** (`["CALL", caller, callee, argc]`, with a non-numeric count decoding to `MalformedTuple` like any other unrepresentable tuple); **binary wire** (`OP_CALL = 20`, count carried as a raw varint like BODY spans so repeated small counts never pollute the string table, and deliberately **no version-byte bump** — a reader predating the opcode fails loudly with `UnknownOpcode(20)` rather than mis-decoding, so previously persisted `0x03` streams keep their established interpretation, including the `data[2] == VERSION` BODY-span rule); **delta** (`CALL:{caller}:{callee}:{argc}` primary key, all three operands in the key tuple, `CL` abbreviation/expansion, and explicit arms in the tuple-based replay helpers so a known opcode never reaches the unknown-opcode fallback that warns in debug builds); **hierarchical IR** (a flat, typed `HierarchicalCall { caller, callee, explicit_arg_count }` table on the container — flat like `imports`/`type_aliases` because the caller is already carried explicitly and the nesting adds no shared context to compress, and typed so a malformed document fails decoding loudly instead of silently defaulting an argument count). Positional, tagged and string-table encodings required no change at all: they are built on `wire::op_to_tuple`/`tuple_to_op` and inherit the new opcode by construction. (`src/ir/opcodes.rs`, `src/ir/wire.rs`, `src/ir/binary_wire.rs` + `src/ir/binary_wire/decode.rs` (new), `src/ir/delta.rs` + `src/ir/delta/compact.rs` / `src/ir/delta/tuples.rs` (new), `src/ir/hierarchical.rs` + `src/ir/hierarchical/encode.rs` / `src/ir/hierarchical/decode.rs` (new))

* **`SemanticEdge` call evidence** — explicit invocation arity is semantic evidence and must survive to the workspace index, so `SemanticEdge` gained `call_evidence: Option<CallEvidence>`, where `CallEvidence { explicit_arg_count }` is a typed, hashable payload rather than generic JSON. It participates in edge-occurrence identity while never entering `EntityKey` and never being encoded into an entity name (Model C identity is unchanged), and `skip_serializing_if` leaves the serialized shape of every non-call edge byte-identical. All existing framework producers (Angular, NgRx, .NET, Spring, testing, builtin) set `call_evidence: None` and remain unaware of call-specific fields. (`src/layers/meta/semantic.rs`, plus the field at every existing construction site)

* **Native generic call relationships — the `Calls` producer, projection, and workspace integration (C#)** — the `Calls` fact now has a producer and reaches `WorkspaceIndex`, so `workspace_query` answers `reverse_edges` for `domain = "builtin"`, `entity_type = "Method"` with Clean-CTX-authored callers. A C# invocation capture query (`queries::CS_CALL_QUERY`, deliberately separate from `CS_QUERY` so the compression and diff paths cannot observe it) binds the callee NAME node at the call site plus each individual `argument` node; `src/ir/calls.rs` assembles the normalized fact from those captures on the SAME tree-sitter parse (both query halves are concatenated into one `Query`, and `run_capture_pipeline_nodes` exposes query-match identity so the captures of one invocation are joined exactly). Explicit argument count is therefore structural — `Foo()` is 0, `Foo(a, b)` is 2, `Foo(new Dictionary<string, int>())` is 1, `items.OrderBy(x => x.Name, direction)` is 2 with the receiver excluded — never `split(',')`, regex, or a second parse. Caller attribution is span-based: `PassContext` tracks open callable scopes exactly like `type_scopes`, so the caller is the innermost callable declaration whose `[start_byte, end_byte)` window contains the invocation (constructors included), and an invocation with no precisely identified callable owner emits NO fact rather than guessing class or file ownership. `src/ir/semantic_projection.rs` owns the single language-agnostic projection (`CoreOp::DefMethod` → callable registration occurrence; `CoreOp::Call` → `SemanticRelation::Calls` with `CallEvidence`), invoked once at the compilation boundary in `IRCompiler::compile_inner`, plus the smallest generic method-registration projection so method-level `builtin / Method` entities resolve in `find_entities`, `forward_edges`, and `reverse_edges`. `WorkspaceIndex` occurrence identity gained the observed argument count for `Calls` (argc 1 and argc 2 for one file/caller/callee are two facts; identical facts remain one occurrence; every non-call relation is unchanged), `has_cycle` excludes `Calls` narrowly, `transitive_dependencies` is untouched, `GraphEdge::Calls` carries `explicit_arg_count` verbatim in both builders, the IRPAT-001 orphan guard (`op_is_unrepresentable_method_ref` plus the centralized `trailing_region_references_call` decline) prevents any consumptive pattern from orphaning a surviving call's caller identity, and validator rule `E011` reports a `CALL` whose caller no longer exists. (`src/queries.rs`, `src/compression/capture_pipeline.rs`, `src/ir/calls.rs`, `src/ir/semantic_projection.rs`, `src/ir/pipeline.rs`, `src/ir/pipeline/core.rs`, `src/ir/compiler.rs`, `src/ir/patterns.rs` + `patterns/recognize.rs`, `src/ir/validator.rs`, `src/ir/program_graph.rs`, `src/workspace/index/{edges,traversal}.rs`)

### Fixed

* **`workspace_query` edge results were not scoped to the queried workspace** — `forward_edges` and `reverse_edges` answered with every occurrence of the requested semantic identity in the whole session, so a query issued for one repository included real, semantically valid facts authored by an unrelated repository that merely happened to be compiled into the same session `WorkspaceIndex` (live: a wanted repository's `OrderBy(argc=2)` callers plus three genuine `OrderBy(argc=2)` callers from another repository). The handlers discarded occurrence provenance at the query boundary: `forward_edges_by_identity` / `reverse_edges_by_identity` select the whole adjacency bucket and hand back only `&SemanticEdge`, while the stored occurrence's asserting file (`StoredEdge::asserting_file`) stayed behind — and because semantic identity is deliberately file-free (`EntityKey` = `(domain, entity_type, name)`, Model C, unchanged: no file/project/root/arity added, no entity renaming, no change to `OrderBy` identity), identity could never separate the repositories. The fix is a query-time **view**, never a mutation. `WorkspaceScope` (`src/workspace/scope.rs`) is built from the query's `workspaceRoot` plus that workspace's configured `additional_roots` (the session holds one flat root configuration with no per-primary association, so a configured additional root participates in every scoped query while an **unconfigured** repository never does), canonicalized through the same `canonical_identity_key` helper that produces production asserting-file keys (so both sides of the comparison share one canonical form, Windows `\\?\` prefixes included), and containment is path-component aware so `C:\repo` never admits `C:\repo-old`. `WorkspaceIndex` gained `forward_edges_by_identity_in_scope` / `reverse_edges_by_identity_in_scope`, which filter INSIDE the already-selected adjacency bucket by `asserting_file` — cost proportional to that identity's occurrence bucket, with no full-index scan, no rediscovery, no recompilation, no new path cache and no new global index — and the two edge handlers now use them. The unscoped lookups are unchanged, and a query that declares no `workspaceRoot` stays unscoped exactly as before. For a call fact the asserting file is the CALLER's file, so an unresolved or cross-repository callee (which may have no local declaration at all) never affects admission. Nothing is removed from `WorkspaceIndex`, and no cache, hydration rule (`WSC-001`/`WSC-002`/`WSC-003`), arity or call-resolution semantics changed. (`src/workspace/scope.rs` (new), `src/workspace/mod.rs`, `src/workspace/index.rs`, `src/mcp/tool_handlers/query.rs`, `src/tests/mcp/workspace_query_scope.rs` (new), `src/tests/mcp/workspace_query_scope_provenance.rs` (new), `src/tests/mcp/workspace_query.rs`, `docs/agent/DISCOVERY_REGISTRY.md` — field finding `DIS-2026-018`)

## [0.6.8] - 2026-09-16

### Added

* **Session-level hydration discovery caching** — `workspace_query` hydration already declined to re-*compile* a candidate file (`WorkspaceIndex::file_map()`), but it had no memory of having already *searched* for a semantic target: every eligible call re-ran the CBM project search (including its lazy-reindex gate) and/or the full filesystem walk-and-read of the root, rediscovering the same candidates only to discard them as already compiled, so the expensive half of hydration was repeated on every identical query. Discovery *completion* is now session state (`src/mcp/discovery_cache.rs`): a `DiscoveryScope` is (provider, canonical root identity) and a completed entry is scope + discovery mode + entity name, recorded against the scope's current generation, so validity is a generation comparison and invalidation is O(1) per scope with no entry scan, eviction, TTL, or size cap. Providers are separate scopes (`Cbm` / `Filesystem`), so a CBM-completed project can never suppress the filesystem fallback its root would otherwise receive, and roots are independent (an additional root is discovered on its own). Discovery-mode equivalence was established from the implementation rather than assumed: `find_entities`, `forward_edges` and `transitive_dependencies` perform the identical declaration search and share one entry, while `reverse_edges` (inbound-reference discovery) keeps its own. Only *successful* discovery is recorded — including a successful discovery that found zero candidates — while failed, partial, still-indexing and CBM-unavailable discovery are never recorded, so a transient failure cannot be cached as absence and stays retryable. The cache stores no candidates, entities, edges, or answers: `WorkspaceIndex` remains the sole authority for query evaluation and every answer is still evaluated against the live index, with only the discovery step skipped. Invalidation reuses existing lifecycle events rather than adding a watcher, timer, or background worker: a successful `apply_edit` invalidates the edited file's root (both providers) and invalidates every scope when the path matches no configured root; an explicit `index_repository` refresh — through the single `cbm_proxy` funnel, whose documented purpose is external edits Clean-CTX cannot observe — invalidates that repository's root; and the source cache's existing mtime/size staleness path drops the whole cache when the session re-reads an externally modified file (files the session never reads remain the documented external-edit boundary). `ensure_indexed_for` is deliberately skipped on a hit: its only in-session dirty producer is `apply_edit`, whose invalidation forces rediscovery, and every other CBM consumer resolves its own indexing gate, so calling it merely to validate the cache would defeat the optimization. No caps, timeouts, TTLs, eviction, persistent or cross-session caches, background invalidation workers, single-flight/coalescing infrastructure, or parallel `WorkspaceIndex` mutation were introduced, and serial candidate compilation is unchanged (a separate follow-up). Recorded as invariant `WSC-003`. (`src/mcp/discovery_cache.rs` (new), `src/mcp/state.rs`, `src/mcp/state/source_cache.rs` (new — `CacheEntry` / `read_source` / `resolve_cache_key` / `invalidate_source_cache` relocated out of the legacy-oversized `state.rs`, which the new field made active), `src/mcp/tool_handlers/hydration.rs`, `src/mcp/tool_handlers/hydration/cache.rs` (new), `src/mcp/tool_handlers/hydration/invalidation.rs` (new), `src/mcp/tool_handlers/hydration/test_support.rs` (new), `src/mcp/tool_handlers/hydration/filesystem.rs`, `src/mcp/tool_handlers/edit.rs`, `src/cbm/proxy.rs`, `src/mcp/mod.rs`, `docs/ARCHITECTURAL_INVARIANTS.md`, `docs/CLAUDE_INTEGRATION_RULES.md`)

## [0.6.7] - 2026-09-16

### Fixed

* **Per-result `search_graph` caller verification** — the C# caller-verification layer derived ONE verification target for the whole `search_graph` response and gated it on result cardinality (`(results.len() == 1).then(...)`), so a broad search skipped verification entirely: an unanchored `name_pattern = "OrderBy"` returned four matches, none was annotated, and the custom overload surfaced CBM's raw overload-conflated `in_degree` with nothing marking it unverified — indistinguishable from a verified count — while the anchored `^OrderBy$` search verified that same symbol correctly. Verification is now planned per result: every result carrying `in_degree` either runs the unchanged shared C# arity verifier on its own (one `VerificationRequest` per eligible result, reusing the single-target request/result types — no duplicated arity algorithm and no search-specific verifier) or is annotated with explicit raw-unverified evidence. Each result carries its own truth (`raw_in_degree`, `verified_in_degree`, `in_degree_evidence`, `in_degree_resolution`, plus `in_degree_reason` for every non-verified verdict), attached to the result it was computed for (the planned response position, confirmed against that entry's stable `qualified_name`); a result whose identity occurs more than once is reported ambiguous instead of being guessed, so an unattributable entry can never annotate a different overload, and one unverifiable or ambiguous result no longer suppresses verification of its neighbours. Eligibility stays scoped to callable C# symbols (non-callable labels, non-C# targets, and identity-less entries cost no CBM query and no source read), and `in_degree_evidence` keeps its existing `cbm_raw` value wherever compatible callers were established, so the previously working anchored case is byte-identical. The top-level `clean_ctx_caller_verification` block keeps its existing field set — identity and arity survive only while every folded target agrees — and adds `results_total` plus `results_verified` / `results_ambiguous` / `results_rejected_or_adjusted` / `results_unverifiable` / `results_not_eligible`, which partition `results_total`, with a weakest-link resolution across the folded targets. `trace_path` and `query_graph` remain single-target surfaces, `WorkspaceIndex`, CBM graph counts, and the arity algorithm are untouched, and no caps, timeouts, concurrency, or caching policy were introduced. Recorded as invariant `CBM-VERIFY-001` and discovery `DIS-2026-017`. * **Thread-isolated handler response capture** — full-suite validation exposed a second test-only race: parallel handler tests could clear or pop another thread's response from the process-global `CAPTURED_RESPONSES` vector. The existing lock-shaped API now fronts a per-test-thread queue, preserving every caller while preventing cross-test response theft; production stdout serialization and JSON-RPC output are unchanged. (`src/protocol.rs`, `src/tests/protocol.rs`)
* **`reverse_edges` inbound CBM query syntax** — the inbound-reference discovery query used `WHERE type(r) <> 'DEFINES' AND type(r) <> 'DEFINES_METHOD'`, which CBM's Cypher parser rejects (parser error lands on the `type(` expression). The query was rewritten to project `type(r)` in `RETURN` and filter client-side in a new `filter_inbound_reference_row` helper that discards `DEFINES`/`DEFINES_METHOD` rows. This eliminates the repeated per-project query failures that opened the shared CBM circuit breaker after three failures, disabling unrelated CBM-backed operations for the rest of the session. CBM still contributes candidate file paths only; relationship type is used solely to discard definition-only rows and never enters WorkspaceIndex as a semantic edge. (`src/cbm/project_search.rs`, `src/tests/cbm/project_search.rs`)
