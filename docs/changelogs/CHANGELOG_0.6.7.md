## [0.6.7] - 2026-09-16

### Fixed

* **Per-result `search_graph` caller verification** — the C# caller-verification layer derived ONE verification target for the whole `search_graph` response and gated it on result cardinality (`(results.len() == 1).then(...)`), so a broad search skipped verification entirely: an unanchored `name_pattern = "OrderBy"` returned four matches, none was annotated, and the custom overload surfaced CBM's raw overload-conflated `in_degree` with nothing marking it unverified — indistinguishable from a verified count — while the anchored `^OrderBy$` search verified that same symbol correctly. Verification is now planned per result: every result carrying `in_degree` either runs the unchanged shared C# arity verifier on its own (one `VerificationRequest` per eligible result, reusing the single-target request/result types — no duplicated arity algorithm and no search-specific verifier) or is annotated with explicit raw-unverified evidence. Each result carries its own truth (`raw_in_degree`, `verified_in_degree`, `in_degree_evidence`, `in_degree_resolution`, plus `in_degree_reason` for every non-verified verdict), attached to the result it was computed for (the planned response position, confirmed against that entry's stable `qualified_name`); a result whose identity occurs more than once is reported ambiguous instead of being guessed, so an unattributable entry can never annotate a different overload, and one unverifiable or ambiguous result no longer suppresses verification of its neighbours. Eligibility stays scoped to callable C# symbols (non-callable labels, non-C# targets, and identity-less entries cost no CBM query and no source read), and `in_degree_evidence` keeps its existing `cbm_raw` value wherever compatible callers were established, so the previously working anchored case is byte-identical. The top-level `clean_ctx_caller_verification` block keeps its existing field set — identity and arity survive only while every folded target agrees — and adds `results_total` plus `results_verified` / `results_ambiguous` / `results_rejected_or_adjusted` / `results_unverifiable` / `results_not_eligible`, which partition `results_total`, with a weakest-link resolution across the folded targets. `trace_path` and `query_graph` remain single-target surfaces, `WorkspaceIndex`, CBM graph counts, and the arity algorithm are untouched, and no caps, timeouts, concurrency, or caching policy were introduced. Recorded as invariant `CBM-VERIFY-001` and discovery `DIS-2026-017`. (`src/cbm/caller_verify_search.rs`, `src/cbm/caller_verify_proxy.rs`, `src/cbm/caller_verify.rs`, `src/cbm/mod.rs`, `docs/ARCHITECTURAL_INVARIANTS.md`, `docs/agent/DISCOVERY_REGISTRY.md`)
