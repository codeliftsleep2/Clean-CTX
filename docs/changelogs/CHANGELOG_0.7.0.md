## [0.7.0] - 2026-09-17

### Added

* **Generic `Calls` IR fact — the instruction and its full serialization contract** — Clean-CTX had no way to express an invocation at all: `CoreOp` carried definitions, signatures, relationships, imports, control flow, and verbatim bodies, but no call/invoke variant, which is precisely why `GraphEdge::Calls` and `SemanticRelation::Calls` both existed as unreachable scaffolding with no producer. `CoreOp::Call(caller_method_id, callee_name, explicit_arg_count)` now carries exactly one structural invocation fact: the innermost callable containing the call in the same file, the callee name **as written at the call site**, and the number of explicitly written arguments (structural, from the argument-list node — never from `split(',')`, regex, or line scanning). The callee is deliberately a NAME and not a resolved declaration identity, because a call site carries no type information: two calls differing only in argument count stay distinguishable, two calls differing only in argument type remain honestly indistinguishable, extension-method receivers are never added to the count, and optional/`params` compatibility is never evaluated (that belongs to later resolution logic, if any). `CoreOp::call_parts()` mirrors the existing `body_span()` accessor so consumers that reason about invocations do not re-match the variant. Every hand-written encoding was extended rather than regenerated: **named wire** (`["CALL", caller, callee, argc]`, with a non-numeric count decoding to `MalformedTuple` like any other unrepresentable tuple); **binary wire** (`OP_CALL = 20`, count carried as a raw varint like BODY spans so repeated small counts never pollute the string table, and deliberately **no version-byte bump** — a reader predating the opcode fails loudly with `UnknownOpcode(20)` rather than mis-decoding, so previously persisted `0x03` streams keep their established interpretation, including the `data[2] == VERSION` BODY-span rule); **delta** (`CALL:{caller}:{callee}:{argc}` primary key, all three operands in the key tuple, `CL` abbreviation/expansion, and explicit arms in the tuple-based replay helpers so a known opcode never reaches the unknown-opcode fallback that warns in debug builds); **hierarchical IR** (a flat, typed `HierarchicalCall { caller, callee, explicit_arg_count }` table on the container — flat like `imports`/`type_aliases` because the caller is already carried explicitly and the nesting adds no shared context to compress, and typed so a malformed document fails decoding loudly instead of silently defaulting an argument count). Positional, tagged and string-table encodings required no change at all: they are built on `wire::op_to_tuple`/`tuple_to_op` and inherit the new opcode by construction. (`src/ir/opcodes.rs`, `src/ir/wire.rs`, `src/ir/binary_wire.rs` + `src/ir/binary_wire/decode.rs` (new), `src/ir/delta.rs` + `src/ir/delta/compact.rs` / `src/ir/delta/tuples.rs` (new), `src/ir/hierarchical.rs` + `src/ir/hierarchical/encode.rs` / `src/ir/hierarchical/decode.rs` (new))

* **`SemanticEdge` call evidence** — explicit invocation arity is semantic evidence and must survive to the workspace index, so `SemanticEdge` gained `call_evidence: Option<CallEvidence>`, where `CallEvidence { explicit_arg_count }` is a typed, hashable payload rather than generic JSON. It participates in edge-occurrence identity while never entering `EntityKey` and never being encoded into an entity name (Model C identity is unchanged), and `skip_serializing_if` leaves the serialized shape of every non-call edge byte-identical. All existing framework producers (Angular, NgRx, .NET, Spring, testing, builtin) set `call_evidence: None` and remain unaware of call-specific fields. (`src/layers/meta/semantic.rs`, plus the field at every existing construction site)

* **Native generic call relationships — the `Calls` producer, projection, and workspace integration (C#)** — the `Calls` fact now has a producer and reaches `WorkspaceIndex`, so `workspace_query` answers `reverse_edges` for `domain = "builtin"`, `entity_type = "Method"` with Clean-CTX-authored callers. A C# invocation capture query (`queries::CS_CALL_QUERY`, deliberately separate from `CS_QUERY` so the compression and diff paths cannot observe it) binds the callee NAME node at the call site plus each individual `argument` node; `src/ir/calls.rs` assembles the normalized fact from those captures on the SAME tree-sitter parse (both query halves are concatenated into one `Query`, and `run_capture_pipeline_nodes` exposes query-match identity so the captures of one invocation are joined exactly). Explicit argument count is therefore structural — `Foo()` is 0, `Foo(a, b)` is 2, `Foo(new Dictionary<string, int>())` is 1, `items.OrderBy(x => x.Name, direction)` is 2 with the receiver excluded — never `split(',')`, regex, or a second parse. Caller attribution is span-based: `PassContext` tracks open callable scopes exactly like `type_scopes`, so the caller is the innermost callable declaration whose `[start_byte, end_byte)` window contains the invocation (constructors included), and an invocation with no precisely identified callable owner emits NO fact rather than guessing class or file ownership. `src/ir/semantic_projection.rs` owns the single language-agnostic projection (`CoreOp::DefMethod` → callable registration occurrence; `CoreOp::Call` → `SemanticRelation::Calls` with `CallEvidence`), invoked once at the compilation boundary in `IRCompiler::compile_inner`, plus the smallest generic method-registration projection so method-level `builtin / Method` entities resolve in `find_entities`, `forward_edges`, and `reverse_edges`. `WorkspaceIndex` occurrence identity gained the observed argument count for `Calls` (argc 1 and argc 2 for one file/caller/callee are two facts; identical facts remain one occurrence; every non-call relation is unchanged), `has_cycle` excludes `Calls` narrowly, `transitive_dependencies` is untouched, `GraphEdge::Calls` carries `explicit_arg_count` verbatim in both builders, the IRPAT-001 orphan guard (`op_is_unrepresentable_method_ref` plus the centralized `trailing_region_references_call` decline) prevents any consumptive pattern from orphaning a surviving call's caller identity, and validator rule `E011` reports a `CALL` whose caller no longer exists. (`src/queries.rs`, `src/compression/capture_pipeline.rs`, `src/ir/calls.rs`, `src/ir/semantic_projection.rs`, `src/ir/pipeline.rs`, `src/ir/pipeline/core.rs`, `src/ir/compiler.rs`, `src/ir/patterns.rs` + `patterns/recognize.rs`, `src/ir/validator.rs`, `src/ir/program_graph.rs`, `src/workspace/index/{edges,traversal}.rs`)

* **Native generic call relationships — the `Calls` producers for TypeScript and Java** — the `Calls` fact now has a producer for both remaining languages, so `workspace_query` answers `reverse_edges` for `domain = "builtin"`, `entity_type = "Method"` with Clean-CTX-authored TypeScript and Java callers, with no CBM-supplied call relationship and no change to the C# path. The language adapter is exactly the grammar boundary the C# milestone left open: `queries::TS_CALL_QUERY` (TypeScript `call_expression`, binding the callee NAME node — a plain `identifier` or a `member_expression` `property_identifier` — plus one capture per explicitly written argument) and `queries::JAVA_CALL_QUERY` (Java `method_invocation`, whose `name` field carries the callee for both receiver-less and receiver-ful forms), each mapped from its base query in `crate::ir::calls::call_capture_query`. Both queries are deliberately separate from `TS_QUERY`/`JAVA_QUERY`, so the compression and diff paths cannot observe a call capture; the observed arity is structural (the `expression` supertype, plus `spread_element` for TypeScript) rather than `split(',')`, a regex, a line scan, or a second parse; a type-argument list is a sibling field and never enters the callee name; and every invocation rides the single existing tree-sitter parse. Deliberately unmatched forms emit NO fact rather than a guessed one — object creation (`new Foo()` / `object_creation_expression`), Java `super(...)`/`this(...)` (`explicit_constructor_invocation`), method references, TypeScript computed member access (`foo[bar]()`), `#private` member calls, tagged template calls, and any invocation with no precisely identified callable owner (a plain field initializer such as `x = foo()`, a top-level statement, or an arrow whose binding carries no stable written name). A BOUND arrow declaration — a class property or variable binding whose value is an arrow function — now owns its calls; see the bound-arrow callable identity entry above. Everything downstream is shared and untouched: `CoreOp::Call`, `CallEvidence`, `SemanticRelation::Calls`, `GraphEdge::Calls`, `WorkspaceIndex` occurrence identity, the traversal policy, `IRPAT-001`, and `E011`. (`src/queries.rs`, `src/ir/calls.rs`, `src/compression/capture_pipeline.rs` test instrumentation, `src/tests/ir/calls_typescript.rs`, `src/tests/ir/calls_java.rs`, `src/tests/mcp/workspace_query_calls_languages.rs`)

* **Spread-qualified call evidence — the written argument count can no longer be read as an exact arity** — `foo(a)` and `foo(...args)` both write exactly one argument node, so the normalized call fact published the same evidence for a call that proves one argument and a call that expands into an unknown number of them; `WorkspaceIndex` occurrence identity then collapsed the two into one occurrence and silently discarded the fact whose count is not an arity. `CoreOp::Call` gained the language-neutral qualifier `has_spread`, derived from the same tree-sitter capture walk that already produced the fact (a TypeScript `spread_element` now binds its own `@call.spread` capture role; the written count still increments exactly once, so `foo(...args)` stays argc 1 and `foo(a, ...rest)` stays argc 2). It is carried by a DUAL SHAPE everywhere: the named tuple keeps its established `["CALL", caller, callee, argc]` bytes for an exact call and adds a fifth `"spread"` operand only when the count is not exact; the binary wire keeps `OP_CALL` byte-identical and gives the qualifier its own additive `OP_CALL_SPREAD` opcode (a reader that predates it fails loudly with `UnknownOpcode(21)` rather than decoding a spread call as an exact one — the established no-version-bump precedent); the delta primary key doubles as `CALL:{caller}:{callee}:{argc}` / `CALL:{caller}:{callee}:{argc}:spread` and the delta key tuple carries the qualifier as an identifying operand, so the delta transport cannot reproduce the same collapse; the positional encoder and the tuple-generic string-table encoder round-trip both shapes unchanged; and `HierarchicalCall` carries it as an optional `s` field that is skipped when false. `CallEvidence` gained `has_spread` (skipped when false, so an exact call edge serializes byte-identically and the qualifier appears only where the count is not an arity), `WorkspaceIndex::EdgeKey` gained it so the two occurrences both survive, and `CoreOp::call_parts()` now returns the qualifier with the count so no consumer can read one without the other. C# and Java call syntax has no caller-side expansion operator, so those facts are always exact; `GraphEdge::Calls` deliberately omits the marker because the local `ProgramGraph` neither keys nor deduplicates its edges and performs no arity resolution. No exact-arity or overload-resolution behaviour was added: this is evidence preservation only. (`src/ir/opcodes.rs`, `src/ir/calls.rs`, `src/ir/wire.rs`, `src/ir/binary_wire.rs`, `src/ir/binary_wire/decode.rs`, `src/ir/delta.rs`, `src/ir/delta/tuples.rs`, `src/ir/hierarchical.rs`, `src/ir/hierarchical/encode.rs`, `src/ir/hierarchical/decode.rs`, `src/ir/semantic_projection.rs`, `src/ir/program_graph.rs`, `src/ir/patterns/recognize.rs`, `src/ir/pipeline.rs`, `src/ir/pipeline/core.rs`, `src/layers/meta/semantic.rs`, `src/workspace/index/edges.rs`, `src/queries.rs`)

* **Verified caller identity is retained and reaches the response** — caller verification narrowed CBM's raw candidate count correctly and then threw away the identity it had established: `CallerVerificationSummary` reported only counters (`verified`, `verified_caller_files`, …), so learning *which* caller/file verified required another CBM `query_graph` round-trip — the very cost verification exists to remove. The summary now carries structured evidence beside every unchanged counter: `verified_candidates` and `ambiguous_candidates`, each holding CBM's projected caller file (`cbm_file` — advisory candidate identity, never promoted to a Clean-CTX semantic fact), the path Clean-CTX actually read after the trusted-path gate (`file`), the distinct accepted explicit argument counts (`argument_counts`, sorted) and its own `status`. Rejected candidates stay counted rather than enumerated (no response-size inflation), a candidate whose source contradicts it is never reported as verified, and ambiguity is never presented as a unique resolution. The evidence reaches every surface — the `clean_ctx_caller_verification` block of `trace_path`/`query_graph`/`search_graph` plus per-result `verified_candidates`/`ambiguous_candidates` on each `search_graph` result — so identity recovery needs no second lookup. (`src/cbm/caller_verify.rs`, `src/cbm/caller_verify_proxy.rs`, `src/cbm/caller_verify_search.rs`)

* **Project-scoped cached candidate discovery and one-parse-per-file verification batches** — verification discovered candidates through `GraphBridge::proxy_call`, the raw pipe path that participates in no cache, so a broad `search_graph` paid a fresh CBM round-trip per eligible result and every request re-read *and re-parsed* its target and candidate files. `GraphBridge::query_graph_scoped(cypher, project)` now serves project-explicit discovery from the **same** cache, TTL, disk write-through and invalidation as `query_graph`, keyed `cypher2:{project}:{cypher}`: the active-project key is valid only while the bridge's active project *is* the queried project (`cbm_proxy` resolves a request's project per call and deliberately does not promote it), and two repositories declaring one symbol name produce identical Cypher text, so a single key would serve one workspace's candidates to the other — entries under the two key shapes can never be read by one another, so WSC-004 isolation holds by construction. A request naming **no** project keeps the original raw call, because it is answered by CBM's own default project, which the active project does not describe and therefore cannot key. One verification batch (one response) now owns a single request-local `ParseMemo` keyed by canonical path, so a file referenced by several results is parsed once; the memo is never persisted, never shared across requests, and is not a source-freshness substitute (`McpState::read_source` still decides which bytes are current). No second cache, persistence or lifecycle was added, and cached discovery never becomes verification truth: source verification still runs and still rejects a contradicted candidate. (`src/cbm/bridge/query.rs`, `src/cbm/caller_verify_arity.rs`, `src/cbm/caller_verify_search.rs`, `src/cbm/caller_verify_proxy.rs`)
* **Bound-arrow callable identity — a named or bound TypeScript arrow now owns its calls** — an arrow expression that is the value of a class property declaration or of a variable binding had no caller identity at all: the callable-span producer opened a scope only for a captured callable declaration (`method.root`, `constructor.root`, `func.root`), and an arrow is never one of those — it is the VALUE of a `public_field_definition` or of a `variable_declarator` — so `class C { load = () => save(); }` and `const load = () => save();` published no fact, even though an invocation inside a nested ANONYMOUS arrow already inherited the enclosing callable's ownership (the confirmed `.subscribe({ next: tp => save(tp) })` attribution, preserved unchanged, and still the reason an object-literal property arrow is deliberately NOT a callable owner). `TS_CALL_QUERY` gained one pattern per declaration form, binding the stable written owner name (`variable_declarator name: (identifier) @arrow.name` / `public_field_definition name: (property_identifier) @arrow.name`) and the arrow declaration itself (`@arrow.root`) in the SAME query match; `CallProducer` joins the pair by query-match identity (`record_arrow_name` / `take_arrow_name`), so a nested arrow can never take another declaration's name and a declaration whose name capture is absent registers nothing at all. The name becomes a `CoreOp::DefMethod` on the innermost open type (or on the existing file-wide synthetic `__file_<file>` class for a module-scope binding), so downstream identity is exactly `builtin` / `Method` / `<name>` — Model C identity, no class-qualified method identity, no arity suffix, and no invented id for an anonymous arrow. Ownership rides the existing `CallableScope` producer unchanged: the arrow's own `[start_byte, end_byte)` participates in the same innermost-span rule, so an invocation in the arrow body belongs to the arrow, an invocation in a nested ANONYMOUS arrow still belongs to this arrow, everything after the arrow's span falls back to the enclosing callable, and a named local arrow becomes the innermost callable while its enclosing method keeps its own invocations — no second ownership algorithm exists. `private` / `readonly` / `static` fields, type annotations, type parameters, `async` and concise expression bodies are the same declaration shape and are all supported; computed/numeric/string/`#private` property names, destructuring bindings, `this.x = () => …` assignments and arrows with no stable written name are structurally excluded and report an honest omission instead of a guessed caller. Nothing else in the pipeline moves: the arrows emit only `DefMethod` (no `Param`/`Return`/`Body`, no layer dispatch, no change to `current_method`, to accumulated method flags, or to body-backed edit units), `TS_QUERY` itself is untouched so the compression capture stream and the diff snapshot cannot observe the new captures, the spread qualifier and written-arity evidence are unchanged, and all detection rides the single existing tree-sitter parse. The documentation claim that arrow bodies emit no fact was false and is replaced by the precise boundary statement. (`src/queries.rs`, `src/ir/calls.rs`, `src/ir/pipeline/core.rs`)
* **`workspace_query` provenance narrowing — an optional `withinPath` inside an already-authorized workspace** — WSC-004 answers WHICH workspace a query is about; it could not answer WHERE inside that workspace, so two feature paths of one repository that declare the same entity name — or `load = () => …` duplicated under `feature-a/` and `feature-b/` — were separable only by re-querying each path as its own workspace ROOT, which would have made the caller's root argument the sole authorization boundary. One optional string argument now composes a second, strictly narrower layer: **effective scope = the authorized root set (`workspaceRoot` + configured `additional_roots`) ∩ `withinPath`**. A relative path resolves against the declared `workspaceRoot` and an absolute path is used as declared — exactly the rule `resolve_file_path` already applies to every other path argument, so no second path-resolution system exists — and the resolved path is canonicalized ONCE per query through the same `canonical_identity_key` helper that produces root and asserting-file keys, so equivalent spellings (relative, absolute, or containing `..`) select one occurrence set. An existing regular FILE narrows to exactly that file (component equality); a directory — or a path that cannot be observed on disk, which keeps a deleted source file selectable by its own path, because provenance stays valid after deletion — narrows to its SUBTREE by the same component-wise ancestry the roots already use, so `feature` never admits `feature-old`. Authorization is decided BEFORE the index is consulted: a `withinPath` that resolves outside every authorized root, or one supplied with no explicit `workspaceRoot` (there would be no authorized set to narrow), is refused with `-32602` and a message naming the resolved path — so the argument can narrow a workspace, never widen one, and can never become a root of its own. Admission remains occurrence PROVENANCE — `EntityRef.file` for entity occurrences, `StoredEdge::asserting_file` for edge occurrences — decided by the very same `WorkspaceScope::admits` the roots already used, which is now the single composed rule `authorized && narrowing`; no query handler grew a path check of its own. `find_entities`, `forward_edges` and `reverse_edges` filter the already-selected bucket (cost proportional to that identity's occurrences, never to the index); `transitive_dependencies` and `has_cycle` apply it DURING traversal, with the start-occurrence guard requiring an occurrence admitted by both layers, so an out-of-path edge can neither extend a walk nor close a cycle; `entities_in_file` keeps its established contract (its explicit `file_path` is already validated against the trusted-path/root boundary) and adds only the second-layer check when a narrowing is present, answering with the pre-existing minimal zero-result shape. Model C identity is untouched, nothing is deleted or re-keyed, and no file read, parse, CBM query, new cache, secondary index, or repository scan is introduced; hydration is deliberately unaffected (candidate discovery stays authorized by the WSC-004 roots alone) and the scope is resolved once per call, so the initial answer and the post-hydration rerun are scoped identically. Omitting the argument leaves every query exactly as it was. (`src/workspace/scope.rs`, `src/mcp/tool_handlers/query.rs`, `src/mcp/tools.rs`)

* **`provide_code_context` returned fabricated method identities for C# generic and tuple-returning declarations** — `CoreOp::DefMethod` is the canonical structured identity of a callable: it feeds the hierarchical wire form, `render_llm` (and its overload grouping), `UnitTable`, and the `builtin` / `Method` registration occurrences that reach `WorkspaceIndex`. Two C# declaration shapes corrupted it, and because the output stayed schema-valid the caller had no signal that semantic fields had been rewritten. (1) The declared name was taken as *the last whitespace token before the declaration's parameter list*, which is only accidentally the name: a generic method's type-parameter list itself contains `, `, so `Pair<TFirst, TSecond>` was read as `TSecond>` — at every fidelity — and the identical rule in `compact_method_low`, `compact_method_medium` and `diff::keys::method_key` corrupted the compressed label and the diff grouping key along with the IR identity. (2) A parameter list was accepted as any depth-0 `(...)` group preceded by an identifier, and `static` is an identifier, so a parenthesized RETURN type was selected as the parameter list: `public static (int alpha, int beta) GetPair(int[] values)` produced name `static`, parameters `int alpha, int beta`, and return type `GetPair(int[] values)`; two unrelated tuple-returning methods then shared the fabricated identity and rendered as an overload group (`M static(+2)`). Both defects live at the same boundary — the flatten-then-reparse contract between `compaction::extract_method_sig` and the IR compiler — so the correction is one structure-first extractor rather than a renderer patch: `src/compaction/signature.rs` (new) derives the declared name from the identifier that OWNS the parameter list (balanced angle-bracket scanning, `.`-qualified chains kept as one name), recognises a parenthesized return type structurally (a `(...)` group that is followed by the declared name and then by the declaration's own parameter list), extracts the trailing TYPE expression of a return-type-first prefix so modifiers and the declaration's own type-parameter list cannot leak into the return type, and splits formal parameters at structural depth so a comma nested inside `Expression<Func<TFirst, TSecond>>` no longer inflates the list. `compaction::method` (Low/Medium labels, `find_method_params`, `extract_param_names`), `ir::pipeline::signature::parse_method_sig` and `diff::keys::method_key` all consume that single implementation, so the IR identity, the compressed label and the diff key now agree by construction; `render_llm` was deliberately untouched (it is a pure projection of `MethodNode`/`ClassNode` fields) and overload grouping gained no special case. A third defect in the same capture-boundary family was fixed with it: `CSharpLayer::extract_class_relationships` scanned the entire class declaration node (head **and** body) for the first `:`, so a ternary inside a member body became a fabricated base class (`X values.OrderByDescending(v => v).First();` on a static class with no base list); the relationship scan now reads only the attribute-stripped declaration head, and a genuine base list is still detected. Cross-language audit and blast radius were established rather than assumed: the shared rule affected C# **and** TypeScript **and** Rust (Java is structurally immune because its method type-parameter list precedes the return type — the control that isolated the defect to the shared flattening and not the renderer), and the same `DefMethod` name is the caller side of every `Calls` edge and the registration occurrence for `builtin` / `Method` entities, so the corruption was never rendering-only — the upstream fix corrects both consumers with no projection change, pinned by regressions at the projection boundary.
