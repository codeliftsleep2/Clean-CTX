## [0.6.6] - 2026-09-15

### Fixed

* **WorkspaceIndex edge-occurrence collision for same-name entities across files/projects** — `EdgeKey` identified an edge by `(relation, subject identity, object identity)` only, so when two files asserted the *same* semantic triple (the live case: `project-a/.../LoadingComponent --Injects--> Router` and `project-b/.../LoadingComponent --Injects--> Router`) the second `add_edges` call hit the dedup gate and `continue`d before recording `file_edges`, `forward`, or `reverse`. The second occurrence's evidence never entered the index: `forward_edges` returned only the first file's `Injects` edges, `reverse_edges` undercounted real consumers of shared services, and removing or recompiling either file destroyed the other file's equivalent evidence (the single shared `edge_set` key was deleted and the adjacency indexes were pruned by entity-reference provenance). Edge identity is now occurrence-aware — `EdgeKey` adds the asserting source occurrence to the semantic triple and the adjacency indexes store `StoredEdge { asserting_file, edge }` — so an edge asserted by one source occurrence can never suppress an equivalent-looking edge asserted by a different source occurrence. Deduplication stays correct at both levels: a repeated extraction of the same triple by the same asserting file still produces one occurrence, while the same triple asserted by a different file is retained as its own evidence record. Semantic entity identity is unchanged (`EntityKey = (domain, entity_type, name)`, file excluded) and no semantic layer, `SemanticRelation`, or query contract was modified — the defect was generic and identical for the Angular, .NET, Spring, and future semantic layers, so the fix lives in `WorkspaceIndex` storage only. `remove_file` is now driven solely by `file_edges[file]` and drops exactly the occurrences that file asserted, so cleanup work stays proportional to the affected file with no whole-index scan, and `resolve_selector` still answers with each entity occurrence exactly once under the new storage. Recorded as invariant `IDX-002` and discovery `DIS-2026-016`. (`src/workspace/index.rs`, `src/workspace/index/edges.rs`, `src/workspace/index/remove.rs`, `src/workspace/index/traversal.rs`, `src/workspace/mod.rs`, `docs/ARCHITECTURAL_INVARIANTS.md`, `docs/agent/DISCOVERY_REGISTRY.md`)
